# Календарь гостевого дома

Личный сервис для дома, который сдаётся целиком: шахматка (календарь занятости), цены и
менеджер каналов (синхронизация с Авито и другими площадками по iCal), уведомления в Telegram.

## Что умеет

- **Календарь.** Два месяца на экране, цена каждой свободной ночи, брони окрашены по площадке.
  Клик по дате заезда, затем по дате выезда открывает форму брони с уже посчитанной суммой.
  Даты можно закрыть без брони (ремонт, своё проживание). Двойную бронь вручную создать нельзя.
- **Статусы брони.** «Бронь» закрывает даты на площадках и идёт в выручку; «Заявка» занимает даты
  только у вас (на площадки не уходит, в календаре заштрихована); «Отмена» освобождает даты.
- **Платежи.** В карточке брони — список оплат и возвратов (дата, способ, комментарий), оплачено,
  остаток или переплата, полоса прогресса. Предоплату можно ввести сразу при создании брони.
  В списке броней — вкладки «Заявки» и «Долги».
- **Статистика.** Дашборд за выбранный период (месяц, год, 12 месяцев, следующие 90 дней, свой
  период) со сравнением с прошлым: выручка (в т.ч. за вычетом комиссий площадок), загрузка, средняя
  цена ночи, доход на ночь, заезды, отмены, глубина бронирования, полученные оплаты и долги; графики
  выручки и загрузки по неделям/месяцам, источники броней, дни недели, срок проживания.
- **О доме.** Страница-справочник для команды: описание, параметры, планировка и спальные места, удобства,
  расположение и ссылка на карту, правила, оплата и отмена, допуслуги; для команды — Wi-Fi, код сейфа,
  инструкция по заселению, контакты. Галерея фото с полноэкранным просмотром; при загрузке фото уменьшаются,
  а геометки и другие метаданные удаляются. Редактирует администратор.
- **Оформление «Пихта».** Логотип с вывески (лыжник со скрещёнными лыжами вместо «Х» и пихты), палитра
  снега и хвои, светлая и тёмная темы, меню для телефона. Страница входа оформлена главным фото дома
  (оно единственное видно без входа) и лёгким снегопадом зимой (отключается при «уменьшении движения»).
  Иконки для вкладки и экрана телефона: календарь можно добавить на главный экран как приложение.
- **Гости.** Справочник: имя, телефон (один номер — один гость, в любом написании), откуда, адрес, e-mail,
  заметки; история броней гостя, сумма и долг. В форме брони гость ищется по имени или телефону, новый
  создаётся сам. Администратор может объединить дубли карточек.
- **Загрузка старых броней** из выгрузки RealtyCalendar (.xls): предпросмотр без изменений в базе,
  сопоставление источников с площадками, прошедшие брони отмечаются оплаченными, строки без гостя с суммой 0
  становятся закрытыми датами; брони на те же даты дополняются, повторная загрузка ничего не задваивает,
  загрузку можно отменить целиком.
- **Пользователи и роли.** Администратор может всё; менеджер — брони, платежи и статистика, цены только
  просмотр, без площадок и управления пользователями. Новых людей администратор приглашает одноразовой
  ссылкой (действует 7 дней, по ней человек сам задаёт логин и пароль) или создаёт вручную. Можно менять
  роль, блокировать доступ и задавать новый пароль; в карточке брони видно, кто её создал и кто внёс платёж.
  Каждый может сменить своё имя и пароль в профиле. Вход защищён от перебора паролей
  (5 неудачных попыток — пауза 15 минут).
- **Цены.** Базовая цена и минимальный срок, правила: цена выходных (по дням недели), сезоны,
  отдельные даты. Изменение цены на период в одну форму. Сумма брони считается автоматически.
- **Менеджер каналов (iCal).**
  - Каждые 10 минут сервис забирает календарь площадки и добавляет, изменяет или отменяет её брони у себя.
  - Площадка забирает наш календарь по секретной ссылке: в нём все занятые даты, кроме её собственных броней.
  - Защиты: пустой календарь площадки (сбой на её стороне) не отменяет брони массово; ответ
    не в формате iCal (устаревшая ссылка или страница входа) считается ошибкой и ничего не меняет;
    смена UID события на площадке не порождает отмену и новую бронь.
- **Telegram.** Сообщения о новых, изменённых и отменённых бронях с площадок, о двойных бронях
  и о сбоях синхронизации.

## Ограничения iCal (важно)

- Передаются **только даты**. Цены и минимальный срок на Авито выставляются вручную (следующий
  шаг — подключить API Авито для краткосрочной аренды, чтобы передавать цены автоматически).
- Площадка забирает наш календарь **по своему расписанию** (от 15 минут до нескольких часов), поэтому
  в этот промежуток возможна двойная бронь. Сервис сразу сообщит о ней в Telegram.

## Запуск на своём компьютере (Windows)

Портативная версия, ничего устанавливать не нужно:

1. Распакуйте `PihtaGeshCalendar-windows.zip` в любую папку.
2. Дважды щёлкните `run_calendar.bat`, при первом запуске придумайте логин и пароль.
3. Откроется браузер с календарём (`http://127.0.0.1:8000`). Окно с чёрным фоном не закрывайте.

Данные лежат в папке `data` рядом с `run_calendar.bat` (`db.sqlite3` — база, `settings.txt` — часовой пояс,
Telegram, порт). Брони с площадок загружаются, пока программа открыта, но площадки не могут забрать
календарь с домашнего компьютера — для двусторонней синхронизации нужен сервер.

Собрать архив заново (на Linux, Python для Windows берётся из NuGet):

```bash
PYTHON=.venv/bin/python scripts/build_windows.sh   # -> dist/PihtaGeshCalendar-windows.zip
```

На macOS и Linux без Docker: `pip install -r requirements.txt && python run_local.py`.

## Развёртывание на сервере

### 1. Что купить

- **VPS в России** (данные гостей по 152-ФЗ должны храниться в РФ): 1 vCPU, 1 ГБ RAM, 10–15 ГБ диска,
  Ubuntu 24.04. Подойдут Timeweb Cloud, Selectel, Beget, REG.RU (ориентировочно 200–500 ₽/мес).
- **Домен** (например, в REG.RU или RU-CENTER), можно поддомен уже имеющегося. В DNS создайте
  A-запись `calendar.ваш-домен.ru → IP сервера`.

### 2. Установка

```bash
# на сервере, под root
curl -fsSL https://get.docker.com | sh
git clone <адрес вашего репозитория> /opt/guesthouse
cd /opt/guesthouse
cp .env.example .env
nano .env            # DOMAIN, SECRET_KEY (команда для генерации — в файле)
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
```

Откройте `https://calendar.ваш-домен.ru` — сертификат HTTPS выпустится автоматически за минуту.

Чтобы сервис открывался ещё и по другим адресам (например, `www.ваш-домен.ru`), перечислите их через пробел
в `EXTRA_DOMAINS` в `.env` (для каждого нужна A-запись на IP сервера) и перезапустите Caddy:
`docker compose up -d --force-recreate caddy`. С этих адресов будет перенаправление на основной.

Если `docker compose` не может скачать образы (Docker Hub бывает недоступен с российских IP),
пропишите зеркало в `/etc/docker/daemon.json`, например `{"registry-mirrors": ["https://mirror.gcr.io"]}`
(или зеркало вашего хостера) и выполните `systemctl restart docker`.

### 3. Подключение Авито

1. В сервисе: «Площадки» → «+ Площадка» → «Авито» → «Сохранить».
2. На **сайте** Авито (в приложении этой настройки нет): объявление → «Управлять календарём» →
   «Синхронизировать календарь с другого сайта».
3. Ссылку «Ваш календарь на Авито» вставьте в сервисе в поле «Ссылка на календарь площадки».
4. Ссылку «Наш календарь для Авито» из сервиса вставьте на Авито и нажмите «Добавить».
5. «Синхронизировать сейчас» — брони с Авито появятся в календаре.
6. Проверка: закройте в сервисе тестовую дату и через 15–60 минут убедитесь, что она закрылась на Авито.
   На странице «Площадки» видно, когда Авито последний раз забирал наш календарь.

Другие площадки (Суточно, ТВИЛ, Циан, Квартирка…) подключаются так же.

### 4. Telegram-уведомления

1. В Telegram напишите @BotFather → `/newbot`, получите токен.
2. Впишите `TELEGRAM_BOT_TOKEN=...` в `.env`, выполните `docker compose up -d`.
3. Напишите своему боту `/start`, затем: `docker compose exec web python manage.py telegram_chat_id`.
4. Впишите полученный `TELEGRAM_CHAT_ID=...` в `.env` и снова `docker compose up -d`.

### 5. Резервные копии (локальные; лучше настроить копии вне сервера — см. «Безопасность»)

```bash
crontab -e
# каждый день в 4:00 — копия базы в /opt/guesthouse/data/backups (хранятся 30 последних)
0 4 * * * cd /opt/guesthouse && docker compose exec -T web python manage.py backup_db
```

Вся база — это один файл `data/db.sqlite3`. Копии стоит периодически забирать с сервера
(например, на Яндекс Диск).

## Безопасность

### В самом календаре

- Заголовки безопасности: HSTS (только HTTPS), Content-Security-Policy (выполняются только свои скрипты,
  встраивать календарь в чужие сайты нельзя), запрет доступа к камере, микрофону и геолокации.
- Служебная админка Django `/admin/` выключена. Включить при необходимости: `ENABLE_DJANGO_ADMIN=1` в `.env`
  (вход в неё всё равно идёт через страницу входа календаря с защитой от перебора).
- Защита входа от перебора паролей, роли, приглашения — см. «Пользователи и роли».

### Защита сервера

1. Создайте SSH-ключ на компьютере (PowerShell; на вопросы просто нажимайте Enter или задайте пароль ключа):
   `ssh-keygen -t ed25519`
2. Скопируйте ключ на сервер (один раз введёте пароль сервера):
   `type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@IP_СЕРВЕРА "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"`
3. Проверьте вход по ключу: `ssh root@IP_СЕРВЕРА` — пароль сервера спрашиваться не должен.
4. На сервере запустите: `bash /opt/guesthouse/scripts/harden_server.sh`. Скрипт отключит вход по паролю
   (только по ключу), включит fail2ban, файрвол (открыты 22, 80, 443) и автоматические обновления безопасности.
5. Не закрывая окно, проверьте вход в новом окне. Если что-то пошло не так — веб-консоль в панели хостинга.

### Резервные копии вне сервера

Копия базы шифруется паролем и раз в сутки отправляется в S3-хранилище (restic); хранятся 14 ежедневных,
8 еженедельных и 12 ежемесячных копий. При ошибке приходит сообщение в Telegram.

1. Создайте бакет в S3-хранилище (например, Yandex Object Storage) и статический ключ доступа.
2. На сервере: `apt-get install -y restic`, затем `cp /opt/guesthouse/scripts/backup.env.example /root/.pihta-backup.env`,
   `chmod 600 /root/.pihta-backup.env` и впишите в файл адрес бакета, ключи и пароль шифрования.
   **Пароль шифрования сохраните отдельно** — без него копии не восстановить.
3. Первый запуск вручную: `bash /opt/guesthouse/scripts/offsite_backup.sh`
4. Ежедневный запуск (заменяет локальную копию `backup_db` — она делается внутри скрипта):
   `(crontab -l 2>/dev/null | grep -v backup_db; echo "30 3 * * * bash /opt/guesthouse/scripts/offsite_backup.sh >> /var/log/pihta-backup.log 2>&1") | crontab -`

Восстановление:

```bash
set -a; . /root/.pihta-backup.env; set +a
restic snapshots                                   # список копий
restic restore latest --target /root/restore       # или ID нужной копии вместо latest
F=$(find /root/restore -name 'db-*.sqlite3' | sort | tail -1); echo "$F"
cd /opt/guesthouse && docker compose stop web worker
cp data/db.sqlite3 data/db.sqlite3.before-restore
cp "$F" data/db.sqlite3 && rm -f data/db.sqlite3-wal data/db.sqlite3-shm
M=$(find /root/restore -type d -path '*/data/media' | head -1); [ -n "$M" ] && cp -r "$M" data/   # фото дома
docker compose start web worker
```

### Аккаунты

Включите двухфакторную защиту в личном кабинете reg.ru (через него можно увести домен) и на GitHub

```bash
cd /opt/guesthouse && git pull && docker compose up -d --build
```

## Локальная разработка

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver          # http://localhost:8000
python manage.py sync_calendars     # синхронизировать один раз
python manage.py test booking       # тесты
```

## Устройство

| Файл | Что внутри |
|---|---|
| `booking/models.py` | Дом, правила цен, площадки, брони, журнал синхронизации |
| `booking/pricing.py` | Расчёт цены ночи, суммы брони и минимального срока |
| `booking/services.py` | Сохранение брони с проверкой пересечений, поиск двойных броней |
| `booking/ical.py` | Экспорт нашего календаря и импорт календарей площадок |
| `booking/notify.py` | Отправка сообщений в Telegram |
| `booking/stats.py` | Расчёт статистики: выручка по ночам, загрузка, источники, распределения |
| `booking/permissions.py` | Роли (администратор / менеджер) и проверка прав |
| `booking/guests.py`, `booking/phones.py` | Справочник гостей, поиск, объединение; приведение телефонов к одному виду |
| `booking/importer.py`, `booking/import_views.py` | Загрузка старых броней из выгрузки RealtyCalendar |
| `booking/accounts.py` | Пользователи, приглашения, профиль, защита входа |
| `booking/management/commands/` | `sync_loop` (фоновая синхронизация), `sync_calendars`, `telegram_chat_id`, `backup_db` |

Стек: Python 3.12, Django 5.2, SQLite (WAL, IMMEDIATE-транзакции), gunicorn/waitress, Caddy (HTTPS),
Docker Compose, Chart.js 4.5 (лежит в `booking/static/booking/vendor`, интернет для графиков не нужен),
шрифт Unbounded (OFL, `booking/static/booking/fonts`), логотип и иконки — `booking/static/booking/brand`.
